### Data Preparation

Our data preparation process consists of two main components:

1. **Data Cleaning**  
   We remove erroneous or low-quality cases identified in the original dataset to ensure a cleaner and more reliable training corpus.

2. **Data Distillation**  
   We perform knowledge distillation to generate high-quality training samples for fine-tuning a smaller model.  
   Since data selection is also involved in this step, the distillation process can be regarded as a more advanced form of data cleaning.

### Original Datasets

The original datasets used in this project are:

- **Big-Vul**: [MSR 20 Code Vulnerability Dataset](https://github.com/ZeoVan/MSR_20_Code_Vulnerability_CSV_Dataset)  
- **Mega-Vul**: [MegaVul](https://github.com/Icyrockton/MegaVul)

### Our Dataset

Our final data with distilled information can be found in ```\final_data```,
and the structure is:
```
final_data/
├── train/ 
│   ├── ordinary_1.json
|   ├── ordinary_2.json     
│   ├── patched.json
│   └── vulnerable.json
└── test/ 
    ├── ordinary.json
    ├── patched.json
    └── vulnerable.json
```
#### Dataset Description

- Vulnerable Code: Code snippets that contain known security vulnerabilities.

- Patched Code: Vulnerable code that has been fixed through patching or modification.

- Ordinary Code: Code that has never been modified and does not contain any known vulnerabilities.

#### Dataset Attribute Descriptions


| Attribute Name         | Type   | Description                                                                                        |
|------------------------|--------|----------------------------------------------------------------------------------------------------|
| `respond_before`       | string | Distilled information generated by a large language model (e.g., GPT) based on the original input. |
| `code`                 | string | The source code snippet under analysis.                                                            |
| `target`               | int    | Indicates whether the code is vulnerable (`1`) or not (`0`).                                       |
| `pair_index`           | int    | Identifier linking a pair of vulnerable and patched code. For ordinary code, this is set to `-1`.  |
| `type`                 | string | Type of the code: `'before'` (vulnerable), `'after'` (patched), `'non'` (ordinary).                |
| `original_information` | string | Additional metadata from the original dataset (e.g., CVE ID, CVE description, CWE ID, etc.).       |
